## نمونهٔ بار محلی

سه حساب مصنوعی، ۳۰۰ پیام و هم‌زمانی ۶ اجرا شد. تمام ۳۰۰ پیام و رویداد Outbox در دیتابیس ثبت شدند. زمان کل ورود حدود ۴۵۶ms، صدک ۹۵ ورود ۱۴٫۴۲ms و صدک ۹۵ خواندن فهرست حساب‌ها ۰٫۵۲ms بود. این اعداد صرفاً baseline دیتابیس محلی‌اند؛ تأخیر شبکه، واتساپ و LLM را شامل نمی‌شوند و تعهد ظرفیت تولید نیستند.

## تکرار بررسی‌ها

دستورات در README و فایل‌های `tests/` موجودند. آزمون‌های یکپارچه، مرورگر، بار، restore و کانتینر از دیتابیس‌های موقت خود استفاده می‌کنند. آزمون کانتینر Redis جدا دارد و منابع خودش را پس از پایان حذف می‌کند. جزئیات آخرین اجرای عملیاتی در `.local/validation/` ذخیره می‌شود؛ این خروجی‌ها در Git قرار نمی‌گیرند.

خطای اولیهٔ فضای Docker با حذف cache ساخت همین پروژه و جداسازی وابستگی‌های توسعه از تصویر اجرایی برطرف شد؛ آزمون کامل پس از اصلاح دوباره اجرا و موفق شد. اعتبارسنجی TLS در نصب و ساخت غیرفعال نشد.

اسکریپت backup برای نصب Docker بدون نیاز به Node میزبان، HMAC را با Python استاندارد تولید می‌کند. بررسی‌کننده‌های Python و Node هر دو در restore آزمایشی و رد ciphertext دست‌کاری‌شده تأیید شدند. دستورهای shell راهنمای مبتدی از نظر نحو و پیوندهای محلی بررسی شدند؛ نصب کامل روی یک VPS تازه با DNS عمومی، از داخل این محیط اجرا نشده است.

## پیش‌نیازهای تأیید زنده

- واردکردن کلید OpenAI از مسیر امن تنظیمات محیط و آزمون مدل انتخابی.
- اسکن QR توسط صاحب حساب آزمایشی، دریافت و تحویل واقعی پیام، قطع/وصل و بازیابی نشست واقعی.
- تعیین دامنه و HTTPS سرور مقصد و اجرای آزمون پذیرش همان استقرار.
- نصب جداگانهٔ سرویس مدل محلی هنگام مهاجرت از OpenAI.

CRM و SMS طبق انتخاب کاربر غیرفعال‌اند. محدودهٔ نسخه و بخش‌های پیشرفتهٔ هنوز پیاده‌نشده در [ماتریس تحویل](architecture/implementation-status.fa.md) آمده است. موفقیت این بررسی‌ها معادل تکمیل تمام فازهای سند یا تأیید Production نیست.

اسکریپت نصب، دستورالعمل شروع، مقصدهای شبکه و نیاز اختیاری کلید `LLM_API_KEY` در پیش‌نویس تنظیمات محیط ابری ذخیره شده‌اند. اعمال دائمی و Snapshot به Review/Save و Publish از تنظیمات محیط نیاز دارد؛ بازیابی در یک task تازه هنوز آزمایش نشده است.
